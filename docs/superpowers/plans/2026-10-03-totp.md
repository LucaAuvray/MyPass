# TOTP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show and copy 2FA codes in MyPass (desktop + PWA), enter the 2FA key in the entry form, and answer the browser extension's `get-totp`.

**Architecture:** One Rust reader for every 2FA consumer: `mypass_core::totp` turns an entry's `otp` link (or legacy `TOTP Seed` + `TOTP Settings`) into `{code, period, secondsRemaining}`. `ops::entries` exposes it by uuid and writes the key on create/update. Desktop, wasm and the native-messaging host only wrap that. The front polls `get_totp_code(uuid)` every second while the code row is shown.

**Tech Stack:** Rust (`totp-rs` 5 with `otpauth`, `url` 2), Tauri v2, wasm-bindgen, React 19 + TanStack Query + react-hook-form/zod, react-i18next.

**Spec:** `docs/superpowers/specs/2026-10-03-totp-design.md`

## Global Constraints

- Storage format: the `otp` field, protected, holding an `otpauth://` link (KeePassXC). Legacy `TOTP Seed` / `TOTP Settings` are read; any save that sets the 2FA key removes them.
- Error strings are exact codes: `TOTP_INVALID`, `TOTP_NONE`.
- `get_totp_code(uuid)` returns JSON `{ "code": string, "period": number, "secondsRemaining": number }`, identical on desktop, wasm and mock.
- IPC parity: every command exists in `tauri::generate_handler!` (`src-tauri/src/lib.rs`), `src/lib/web.ts` and `src/lib/mock.ts`.
- No user-facing string hard-coded: EN + FR keys in `src/i18n/{en,fr}.json`.
- No new crate download: `url = "2"` is already in the tree through `totp-rs`'s `otpauth` feature.
- Never run anything against the production server or a real vault; E2E uses temp data dirs.
- In Git Bash, cargo needs `export PATH="$HOME/.cargo/bin:$PATH"`.
- Commits in English, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Editing entry B after having opened or edited entry A → the form shows B's values, 2FA key included. `EntryForm` today never resets its defaults (react-hook-form caches them at first mount), so saving would copy A's key and password onto B. Fixed and checked in Task 5 and Task 6.
2. Entry shown across a period boundary → the code changes within about 1 s and the bar restarts; a stale code never stays on screen. E2E step in Task 6.
3. Selecting another entry while the code row is shown → the row shows the new entry's code, never the previous one (query key carries the uuid). E2E step in Task 6.
4. Editing only the title of an entry with 2FA → the 2FA survives unchanged (the form sends the prefilled link back). Core test `update_with_same_link_keeps_it` in Task 2, plus an E2E step in Task 6.
5. Vault locked while the code row is shown → polling stops with the row; no error flood. E2E step in Task 6.

- [ ] **Step 3: Implement in `totp.rs`**

- `normalize`:
  - Trim the value. Empty gives `""`.
  - A value starting with `otpauth://` (case-insensitive): parse it with `url::Url`. Clean the `secret` query value: remove whitespace and `=`, uppercase. If cleaning changed it, rebuild the query with the cleaned secret, keeping the other pairs in order. Otherwise, or if the link does not parse, return the trimmed value unchanged.
  - Otherwise: build `otpauth://totp/<percent-encoded title>?secret=<cleaned>`. This is the body of today's `normalize_totp`; move `percent_encode` along with it.
- `entry_otp_uri`:
  - `otp` non-empty: return it.
  - Otherwise `TOTP Seed` non-empty: return `normalize(seed, title)`. If `TOTP Settings` splits on `;` into a `u64` period and a numeric digit count, append `&period=<p>&digits=<d>`.
  - Otherwise `None`.
- `code_at`: `TOTP::from_url_unchecked(uri)`. Any parse error gives `TOTP_INVALID`. Also `TOTP_INVALID` when `secret.is_empty()`, `!(6..=8).contains(&digits)` or `step == 0`, checked **before** `generate`. Then `code = totp.generate(now)`, `seconds_remaining = step - now % step`.
- `code_for_entry`: `entry_otp_uri(entry).ok_or("TOTP_NONE")` then `code_at`.
- `transfer.rs`:
  - import `crate::totp::normalize` in place of `normalize_totp`;
  - `to_imported` takes `totp: crate::totp::entry_otp_uri(e).unwrap_or_default()`;
  - add `"TOTP Settings"` to `STANDARD_KEYS`, which becomes `[&str; 8]`.
