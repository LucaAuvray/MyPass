# Groups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Folders everywhere: tree in the sidebar, list filtering, create / rename / delete (content goes up to the parent), move an entry, and folder changes that sync between devices.

**Architecture:** `mypass_core::ops::groups` owns the folder rules (name check, rename touches the folder, delete dissolves into the parent). `mypass_core::merge` learns folders: LWW on name/icon/notes, folder tombstones (no resurrection, dissolve into parent), and the winning entry brings its folder. The front gets one `useGroups()` hook, pure tree helpers in `src/lib/groups.ts`, a `groupFilter` in the entries store (client-side filtering), and a `GroupsSection` in the sidebar.

**Tech Stack:** Rust (`mypass-core`, Tauri v2, wasm-bindgen), React 19 + TanStack Query + Zustand, Base UI dialogs/menus, react-i18next.

**Spec:** `docs/superpowers/specs/2026-10-03-groups-design.md`

## Global Constraints

- Error string is the exact code `GROUP_NAME_REQUIRED` (blank name, after trim, on create and rename).
- `GroupInfo` JSON is camelCase: `uuid`, `name`, `icon`, `children`, `entryCount`, `isExpanded`, `created`, `modified`; no `parentUuid`. `entryCount` counts the folder and all its subfolders.
- `MergeOutcome` JSON gains `groupsUpdated`, `groupsDeleted`; `changed()` counts them.
- Deleting a folder: entries and subfolders go to the end of its parent; one tombstone only (the folder); the root cannot be deleted.
- IPC parity: `get_groups`, `create_group`, `update_group`, `delete_group`, `move_entry` exist in `tauri::generate_handler!` (already), `src/lib/web.ts` and `src/lib/mock.ts`, same JSON shapes. Tauri arg names from the front: `{ name, parentUuid }`, `{ uuid, name }`, `{ uuid }`, `{ entryUuid, groupUuid }`.
- Folder filter and kind filter are exclusive; ⌘K search stays global.
- No user-facing string hard-coded: EN + FR keys in `src/i18n/{en,fr}.json`.
- Out of scope: drag and drop, moving a folder, recycle bin handling, persisting expanded state.
- Never run anything against the production server or a real vault; E2E uses temp data dirs.
- In Git Bash, cargo needs `export PATH="$HOME/.cargo/bin:$PATH"`. After cargo/tauri runs, `git checkout -- src-tauri/Cargo.toml src-tauri/gen/schemas` if they only show EOL changes.
- Commits in English, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Folder filter pointing to a folder that no longer exists (deleted here, deleted by a sync, vault locked and another opened) → the list falls back to all items, never an empty list with nothing highlighted. Reset in Task 4, E2E step in Task 4 and Task 5.
2. Creating any kind of item (password, identity, card, document, SSH key) while a folder is selected, in the desktop dialog and in the mobile sheet → it lands in that folder; with no folder selected → root. E2E step in Task 4.
3. Moving the entry open in the detail panel → the panel stays on it, its folder label changes, and it leaves the filtered list if moved out of the selected folder. E2E step in Task 4.
4. Deleting a folder that holds entries and subfolders, then syncing the other device → the same content sits in the parent on both, counts match, the folder never comes back. Core test in Task 2, E2E step in Task 5.
5. Whitespace-only name in the create / rename dialog → refused with the translated message, dialog stays open, nothing saved. Core test in Task 1, E2E step in Task 4.

- [ ] **Step 3: Implement in `merge.rs`**

Replace `add_missing_groups` with a walk of the remote tree (root excluded) carrying the *effective local parent*:

```
walk(remote_group, effective_parent):
  for child in remote_group.groups:
    next = if local has child:
             if lmt(child) > lmt(local child): copy name, icon_id, notes, times; groups_updated += 1
             child.uuid
           else if local tombstone for child >= lmt(child):
             effective_parent                      // not recreated; its children go up
           else:
             add empty shell under effective_parent (root if not found); groups_added += 1
             child.uuid
    walk(child, next)
```

Local tombstones and the local tree are disjoint fields of `local.root`: borrow `deleted_objects` immutably while mutating `group`, or collect the needed tombstones first.

In the entries pass, when the remote entry wins: after the replacement, if the remote parent exists locally and is not the entry's current local parent, remove the entry and push it into the remote parent.

After the entry deletions and before the tombstone union: collect every local group (root excluded) whose uuid is absent from the remote tree and whose remote tombstone is `>=` its LMT; `dissolve` each one in turn; `groups_deleted += 1` per success.

Replace the old `ponytail:` comment ("groups are never deleted by the merge") with: `// ponytail: folder position is not merged (no UI moves folders); a folder deleted on one device and renamed on another before sync survives, its subfolders may then sit in different places per device.`
